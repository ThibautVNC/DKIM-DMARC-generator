DKIM/DMARC Helper

For mail rejected by Outlook.com/Hotmail with 550 5.7.1 Message lacks SPF/DKIM/DMARC Auth Records.

1. Domain

Enter the customer's domain. Its public DNS records are checked automatically.

2. Confirm the error

Connect to the correct tenant and confirm the rejection in the message trace.


    
Expected in the failed event: 550 5.7.1 Message rejected: Message lacks SPF/DKIM/DMARC Auth Records. A different code? See the troubleshooting table in step 6.

  


  
  

    
3. Get the DKIM values

    
The DKIM values depend on the tenant and can't be derived from the domain name. Run this and paste the output below.

    

    
    
    

    
"couldn't be found" or "Invalid domain name" means you're connected to the wrong tenant. Check with Get-AcceptedDomain.

  


  
  

    
4. DNS records

    
These records need to be added to the DNS zone.

    

    

    
Always start DMARC at p=none. Other services sending on behalf of the domain, such as the website or a mailing tool, won't get blocked that way.

  


  
  

    
5. DNS host & email to the customer

    
Who manages the DNS?

    

    
    
    
If you manage the DNS yourself, add the records from step 4 and go straight to step 6.

    
Email to the customer

    
The customer forwards the part between the lines to their DNS host.

    

  


  
  

    
6. Finish (after the customer confirms)

    
Only enable DKIM once the records are visible. Before that, you'll get CnameMissing.

    

    
    

    
Check the message source of a test email received on Hotmail/Outlook (Authentication-Results): spf=pass, dkim=pass, dmarc=pass.

Troubleshooting

    

      
SymptomCause / fix

      
CnameMissing when enablingRecords not propagated yet, or the name is wrong (some panels append the domain automatically, which gives selector1._domainkey.domain.domain). Wait 15–30 min.

      
DKIM Valid but still failingOutlook.com may need some time to pick up DMARC. Check the message source after a few hours.

      
5.7.515Authentication insufficient. Same fix as above.

      
S3150 / "on our block list"Microsoft outbound IP is blocklisted. Request delisting via sender.office.com or open a Microsoft ticket.

      
5.1.10 / recipient not foundRecipient address doesn't exist. Check it for typos.

      
5.1.8 / restricted from sendingAccount blocked. Release it in Defender (Restricted entities), reset the password and check MFA.
